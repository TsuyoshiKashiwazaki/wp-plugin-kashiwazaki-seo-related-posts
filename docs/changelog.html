v1.0.4（2026-10-04）

新しくできるようになったこと

  • 関連記事を「意味の近さ」で選ぶようになりました（OpenAI Embeddings、既定は text-embedding-3-small）。記事を公開・更新するとベクトルを自動で作ります。
  • 関連記事の選び方を「意味の近さで選ぶ」「意味の近さ＋GPT」「従来の方式」から選べます。GPT を使う方式でも、訪問者のページ表示中には GPT を呼ばず、バックグラウンドで選びます。
  • 使える embedding モデルと GPT モデルを OpenAI から自動で取得します（取得ボタン付き）。GPT モデルは保存するときに使えるか確かめます。
  • 投稿タイプ別設定に「すべて現在の設定値を反映」ボタンを追加しました。記事ごとに保存された設定を消して、カスタム設定（なければ共通設定）を既存の記事にまとめて効かせます。
  • 設定画面のすべての項目に、説明のツールチップ（「?」）を付けました。
  • 共通設定にスライダー表示数を追加しました。
  • 保存済みの APIキーを、確認ダイアログ付きの「保存済みのキーを削除」ボタンで消せます。wp-config.php の定数でキーを設定することもできます。
  • API 呼び出し統計を GPT と Embedding に分けて表示します。

直した不具合

  • クラシックエディタの投稿編集画面（アンケートなど）で「公開」を押しても下書きとして保存される問題。
  • ショートコードで use_ai を省略すると、APIキーがあっても AI を使わなかった問題。
  • 投稿タイプ別のカスタム設定の「キャッシュ有効期限」「AI分析用候補数追加」「スライダー表示数」が使われず、共通設定の値が使われていた問題。
  • 30 日間のグラフに今日が入っていなかった問題。
  • AI に渡す抜粋が日本語環境で 30 文字に切られていた問題（200 文字に）。
  • 操作ボタンを「関連記事を表示」にチェックが入っている投稿タイプだけに出すようにしました。

セキュリティ

  • OpenAI の APIキーを暗号化して保存し、設定画面の HTML にも出さないようにしました。
  • OpenRouter 関連の処理を削除し、データベースに残っていた OpenRouter のキーを自動で削除します。
  • 管理画面の Chart.js を外部 CDN から読み込まず、同梱しました。

v1.0.3（2026-06-26）

  • 設定保存の全経路に CSRF 対策（nonce 検証と権限チェック）。
  • 見出しタグの格納型 XSS 対策（許可リスト方式）。
  • カテゴリの絞り込みをすべての選び方に適用。
  • アンインストール時に設定・投稿メタを完全に削除（マルチサイト対応）。
